# Notes for agents working on Deckhand

- Recording demos or taking screenshots (README, social preview, videos): turn on the brand palette by setting `"theme": "dusk"` in the config of the Deckhand you record, `~/.deckhand/config.json`, or `~/.deckhand-dev/config.json` for the dev build ([docs/dev-build.md](docs/dev-build.md)). It needs a terminal with 24-bit colour; restart the UI after changing it, and remove the key afterwards. Day to day Deckhand uses the terminal's own colours. See [Colours](docs/features.md#colours) and the [design system](docs/brand/deckhand-design-system.html).
- Tests describe current Rust behavior; new tests need no TS counterpart or port-unit marker. Prefer named scenarios and assertions, keep useful low-churn corpora, and preserve compatibility inputs. See [docs/testing.md](docs/testing.md).
- Changing behaviour that a fixture or snapshot records (a failing `deckhand_testkit` replay or `assert_snapshot`): the TypeScript app is no longer the reference. If the change is intended, rerun only the affected tests with `DECKHAND_BLESS=1`, review `git diff fixtures/`, then rerun without the variable; never bless to silence a failure you have not understood. `fixtures/state` is never blessed. See [parity/README.md](parity/README.md), "Changing behaviour".
