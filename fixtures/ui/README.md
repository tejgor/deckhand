# UI screen snapshots

What the app draws, as text: one line per terminal row, trailing spaces trimmed. Tests render the app (or one pane)
with ratatui's `TestBackend` and compare with `deckhand_testkit::assert_snapshot`; an intended change is updated with
`DECKHAND_BLESS=1` (see `parity/README.md`, "Changing behaviour"), then reviewed in the diff.

- `<nn>-<name>.txt`, used by `crates/ui/src/app/layout.rs`: the whole 130x36 screen.
- `settings/<name>.txt`: named settings scenarios rendered directly from Rust inputs, including selected styles,
  pending trust and narrow-column or choice-editor states.
- `panes/<nn>-<name>.txt`: the right pane of the 130x36 app (98x31) drawn by `app/modes/confirm.rs`,
  `app/modes/create.rs`, `app/modes/action_picker.rs` and `flows/tasks.rs`, at an explicit 98x31 size. A tasks
  snapshot also holds the footer
  hint (after `── hint`) and the styled runs of every row (after `── styles`: `start..end` in columns, then `fg`/`bg`
  and the modifiers that are set).

The snapshots started out as the screens of the TypeScript (Ink) app, which the port matched; everything below this
line describes how those were recorded. The `.json` files and the screens no test names (for example
`07-settings.txt`) are from that recording and are not checked by anything.

## TypeScript recording (history)

Generated by `parity/gen/ui.gen.ts` from the TS (Ink) app. Regenerating them from TS is no longer meaningful.

### Files

- `<nn>-<name>.txt`: the screen rows exactly as displayed after normalisation, trailing spaces trimmed (one line per
  terminal row, so a screen always has `rows` lines).
- `<nn>-<name>.json`: `{name, scenario, cols, rows, keys, script, text, cursor, styles}`.
  - `keys`: every key written to the PTY since the app started, in order (raw bytes as JSON strings).
  - `script`: the replayable steps from the start: `{press}`, `{wait: text}` (wait until the normalised screen
    contains it), `{waitGone: text}`, `{resize: {cols, rows}}` (PTY and terminal both), `{external, args}` (below).
    After the last step the harness waits for idle (the normalised screen unchanged for 700 ms) and captures.
  - `text`: the normalised rows (same as the .txt).
  - `cursor`: `{x, y, visible}` (0-based; `visible` is DECTCEM, Ink hides it).
  - `styles`: per row, the runs of cells whose style is not the default: `{start, end}` (display columns of the
    normalised row, end exclusive) plus only the attributes that are set: `fg`/`bg` (palette index 0-255, or
    `#rrggbb` for true colour), `bold`, `dim`, `italic`, `underline`, `inverse`. Rows without such runs are omitted.

### Environment

Each scenario starts a fresh app: `node dist/cli.js` (no arguments) in a real PTY, 130x36, `TERM=xterm-256color`,
cwd `<TMP>/demo`, where `<TMP>` is `realpath($TMPDIR)/dh-ui-XXXXXX` (removed afterwards) holding:

- `home/`: `DECKHAND_HOME` (the daemon the UI starts lives here; worktrees go to `home/worktrees/<name>`).
- `user/`: `HOME`; `CLAUDE_CONFIG_DIR=user/.claude`, `CODEX_HOME=user/.codex`.
- `bin/`: `claude`, `pi`, `codex` = the `fakeAgent` of tests/helpers.ts; `deckhand-cli.mjs` = a shim importing
  dist/cli.js, which is `TEST_CLI` (the fake agents report hooks with `node $TEST_CLI hook`).
- `demo/`: a git repo (`git init -b main`, user `Deckhand Test <deckhand@example.invalid>`, gpgsign off, hooks off)
  with one commit "initial" of `file.txt` (`first\n`), `README.md` (`# Demo\n\nA repository for UI goldens.\n`)
  and `deckhand.json` (`{"devCommand": "echo dev-ready", "actions": {"test": "echo tests-ok"}}`, 2-space JSON).

The environment is exactly: `PATH=<TMP>/bin:<node dir>:<git dir>:/usr/bin:/bin:/usr/sbin:/sbin`, `HOME`,
`DECKHAND_HOME`, `DECKHAND_DEV=0`, `DECKHAND_AGENT_LATEST={}`, `SHELL=/bin/sh`, `TERM=xterm-256color`,
`LANG=en_US.UTF-8`, `TZ=UTC`, `USER=LOGNAME=deckhand`, `TEST_CLI`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`,
`EDITOR=VISUAL=true`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, and `TMPDIR` when set.

External steps (`{external, args}`) are changes made outside the UI at that point of the script:

- `hook {session, payload}`: what the fake agent of the session titled `session` would send: runs
  `node $TEST_CLI hook` with that session's `DECKHAND_SESSION_ID`, `DECKHAND_LAUNCH_ID`, `DECKHAND_HOOK_TOKEN`
  (from `home/trace-<id>.json`) and stdin `{"session_id": <its native id>, ...payload}` (the native id is the
  `--session-id`/`--resume` argument the fake claude got).
- `write-file {path, content}`: writes the file (`<TMP>` expanded).
- `git {cwd, args, env}`: runs `git -C <cwd> <args>` with `env` added (fixed commit dates, so the commits are the
  same every run) and `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1`.

### Normalisations

Applied in this order to every row before it is stored or compared; each rule rescans the row after a replacement.
A replacement keeps the row's display width: the difference in columns is inserted into (or taken out of, keeping
at least one space between words) the whitespace right after the word the replacement ends in. A replaced span takes
the style of its first cell. Matching is on the row text (wide characters are one character).

| # | rule | pattern | replacement |
|---|------|---------|-------------|
| 1 | temp path | `realpath($TMPDIR)/dh-ui-XXXXXX` (also without the `/private` prefix) | `<TMP>` |
| 2 | temp dir name | `/dh-ui-[A-Za-z0-9]{6}/g` | `<TMP>` |
| 3 | uuid | `/\b[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}\b/g` | `<UUID>` |
| 4 | git sha | `/\b(?=[0-9a-f]*\d)(?=[0-9a-f]*[a-f])[0-9a-f]{7,40}\b/g` | `<SHA>` |
| 5 | spinner frame | `/[⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏]/g` | `⠋` |
| 6 | iso timestamp | `/\b\d{4}-\d\d-\d\dT\d\d:\d\d:\d\d(?:\.\d+)?Z?\b/g` | `<TIME>` |
| 7 | date | `/\b\d{4}-\d\d-\d\d\b/g` | `<DATE>` |
| 8 | clock time | `/\b\d{1,2}:\d\d:\d\d\b/g` | `<CLOCK>` |
| 9 | pid | `/\bpid:? ?\d+\b/gi` | `pid <PID>` |
| 10 | duration | `/\b\d+(?:\.\d+)?(?:ms\|s)\b/g` | `<DUR>` |
| 11 | relative age | `/\b\d+ (?:seconds?\|minutes?\|hours?\|days?) ago\b/g` | `<AGE> ago` |

Waits for idle make the rest stable: every created session is awaited until its agent is idle (no spinner), and
transient status messages are awaited away (`waitGone`) before a screen that must not show them.
