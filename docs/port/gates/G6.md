## Procedure (`scripts/gates/upgrade.mjs`)

1. **Build the v45 daemon.** `git worktree add --detach $TMPDIR/dhu-*/v45 main`. `--detach` is needed because
   `main` is checked out in the primary checkout. Then `npm ci` and `npm run build` inside that worktree. Nothing
   is installed globally; npm uses only its normal download cache.
2. **Start it in a sandbox.** The sandbox has a temp `DECKHAND_HOME` and `HOME`, a one-commit git repo, and fake
   `claude`/`codex`/`pi` (`tests/helpers.ts` `fakeAgent`, trimmed). Start `node v45/dist/cli.js --daemon`
   detached, as a real client would. Over its socket, create two claude sessions, wait until each fake agent has
   reported `SessionStart`, and `kill` the second one. The result is one session `running` and one
   `exited`/`stopped`.
3. **The Rust client refuses.** Run `target/release/deckhand` with no arguments in a PTY (300×30) in the repo. The
   UI is the only client command that pings the daemon (`ensureDaemonRunning`). For comparison, run this tree's
   v46 TS client (`node dist/cli.js`) the same way first; it is the oracle.
4. **Kill the old daemon.** Run `kill <pid>` (SIGTERM) as the message says, and wait for the v45 daemon and the
   agent to exit.
5. **The Rust daemon adopts the state.** Run `target/release/deckhand` again in a PTY. Wait until protocol 46
   answers, then read the sessions over the socket.
6. **Clean up.** Stop the Rust daemon with SIGTERM (`shutdown` is refused outside the dev channel, by TS and Rust
   alike). Check `state.json` on disk, kill leftovers, and delete the sandbox. Then run
   `git worktree remove --force <tmp>/v45`; `--force` is needed because `node_modules/` and `dist/` are untracked.

## Notes

- **The refusal is shown in the UI; the client does not exit.** The client does not exit non-zero when it refuses.
  The UI opens, its status line shows `Error: <message>`, and it stays open until the user quits. This is exactly
  what the v46 TS client does (the oracle run above), so the gate checks for the message on screen, not for an exit
  code. The message is identical byte for byte to TS `ensureDaemonRunning` (src/client.ts:189).
- **The v45 daemon is never replaced.** While it is alive, the Rust client neither spawns a daemon nor removes the
  socket. The old daemon, its worker and the agent all keep running.
- **What a SIGTERM leaves on disk.** On SIGTERM, v45 retires its workers without persisting their exit, so
  `state.json` still says `running` with the old `pid`. The Rust daemon's start-up recovery then turns that into
  `exited`, `exitReason: interrupted`, `exitCode: null`, the `DaemonRestart` attention, and no `pid`. This is the
  same recovery as TS's `markAllNonExitedSessionsExited`. The stopped session's `updatedAt` is untouched, so it was
  not rewritten. `agentSessionRef` is kept, so the session can be resumed.
