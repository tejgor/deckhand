# Typing to an agent in the Preview: follow-ups

**Status:** v1 shipped (protocol v52, shells in v53): `→` on a running session's Preview sends every key to the agent and draws its styled screen and cursor, and `→` on the Terminal tab does the same for the shell shown; `ctrl+]` / `ctrl+space` return. See [docs/features.md](../features.md#typing-to-an-agent-in-the-preview) and HANDOFF.md, *Preview focus: typing to the agent*. What is below is not built.

- **Keyboard-protocol mirroring.** Attach enables nothing beyond bracketed paste either, but a terminal speaking the kitty keyboard protocol (or modifyOtherKeys) sends Shift+Enter as its own sequence only when the program asked for it. Deckhand's UI never asks, so in preview focus Shift+Enter arrives as Enter. A terminal mapping Shift+Enter to `\x1b\r`, and Claude's `\` + Enter, still work. Mirroring would mean turning the protocol on for Deckhand's terminal while the agent has it on (`screen.modes` would carry it) and passing its sequences through unchanged.
- **Clicks.** Only the wheel reaches the agent; a left press, drag and release select the Preview and copy it (`crates/ui/src/app/modes/preview_select.rs`). Forwarding clicks needs the agent's mouse mode (`ScreenModes.mouseTracking` is there already) and must share the left button with selection: a drag selects, a plain click (press and release on one cell, which today only clears the selection) goes to the agent, sent at the release with the press, so the two can be told apart. The coordinate mapping is there (`cell_at`, `preview_focus.body`).
- **Synchronized updates.** The worker broadcasts whatever the emulator holds every 8 ms, even in the middle of a `?2026` synchronized update, so a fast redraw can show a half-drawn frame for one frame. Holding broadcasts until the update ends (with a timeout) would fix it.
